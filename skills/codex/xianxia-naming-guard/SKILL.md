# Xianxia Naming Guard

Use this skill before changing names or creating image prompts for Hermes, Agents, Bots, Notion pages, CLI tools, gateways, web accounts, emails, credentials, avatars, app icons, account IDs, or AI learning records.

The naming universe is xianxia-flavored globally. `NaN Xian` is only one local namespace, currently used for Notion.

## Core Rule

Names must be:

- **Accurate**: the name says what the thing does.
- **Readable**: a future user can understand it without decoding lore.
- **Classic cultivation based**: draw from recognizable 修真/修仙 tropes such as 凡人流、退婚流、化凡、夺舍、双修、闭关、渡劫、结丹、元婴、飞升、掌天瓶、逆天改命, and similar famous genre motifs.
- **Modern meme mixed**: support `修真元素 + 现代流行语/网络热梗` hybrids, as long as the function stays clear.
- **Playful but clean**: witty, cheeky, a bit 骚, and capable of making a 修真迷会心一笑; never use vulgar, sexualized, hateful, or policy-risky wording.
- **Scoped**: pick the right namespace before naming.

## Tone

Default tone: 修真迷一眼看懂，懂梗的人会笑，不懂梗的人也能猜到用途。

Good flavor:

- 像宗门管事给现代 AI 工具发工牌。
- 像老祖把自动化、CLI、Agent、网关都编进宗门制度。
- 有一点“这名字有点骚但很准”的感觉。
- 像公司同事看到会心一笑，但不会觉得尴尬到想截图审判。

Avoid:

- 低俗擦边、冒犯性梗、色情化双关。
- 只顾玩梗导致职责看不懂。
- 生僻到像随机古风生成器。
- 纯古风堆砌，没有现代工具感或实际用途。

## Scope Decision

Before naming, decide the scope:

- **Global systems**: Hermes, Agents, Bots, multi-end robots, CLI tools, gateways, relays, accounts, credentials, and web registrations use the broader xianxia universe.
- **Notion local system**: Notion workspace, pages, databases, and Notion-facing connections can use `NaN Xian·...`.
- **Credentials**: use clear purpose plus flavor; never make the title so poetic that the secret's purpose becomes unclear.

## Global Xianxia Universe Patterns

Choose names by real function:

- **Command relay / robot channel**: `传令使`, `接引使`, `飞书传令阵`, `多端传令阵`.
- **Writing / note capture**: `执笔使`, `书记官`, `手札录`.
- **Monitoring / scheduled jobs**: `值夜使`, `巡天司`, `观星台`.
- **Gateway / relay / proxy**: `中转阵`, `传送阵`, `御器阵`, `通玄门`.
- **Troubleshooting**: `镇魔司`, `降魔录`, `排障司`.
- **Model / CLI / tool invocation**: `法器`, `符箓`, `剑匣`, `阵盘`, `炼器台`.
- **Web account / identity**: keep the service and purpose obvious, then add flavor if useful.

## Classic Trope Palette

Use these as ingredients, not as mandatory templates:

- **凡人流**: for humble bootstrap accounts, first setup notes, entry-level agents, low-key but reliable workflows.
- **退婚流**: for deprecating bad configs, replacing broken vendors, abandoning failed tools, or "I no longer serve this old path" migrations.
- **化凡**: for simplifying complex systems into daily notes, human-readable docs, or non-technical workflows.
- **夺舍**: for migrations, account handoffs, model swaps, agent replacement, or taking over a legacy process. Use carefully and keep the function clear.
- **双修**: only for benign collaboration/pairing metaphors, such as two tools working together; avoid sexualized wording.
- **掌天瓶**: for collection, long-term accumulation, memory, archive, or growth-compounding systems.
- **仙逆 / 逆天改命**: for painful debugging, recovery from failures, or turning broken infrastructure into a working pipeline.
- **闭关 / 出关**: for long-running setup, private iteration, version release, or a tool becoming ready.
- **渡劫**: for risky migrations, auth failures, SMTP/OAuth pain, or major deploy checkpoints.
- **飞升**: for successful launch, production readiness, or a workflow becoming fully automated.

## Meme Mixing Patterns

Prefer short mixed forms:

- `修真元素 + 职责`: `渡劫排障录`, `飞剑传令阵`, `掌天瓶归档阁`.
- `修真元素 + 现代工具`: `CLI剑匣`, `Agent执笔使`, `网关传送阵`.
- `名场面 + 现代行为`: `退婚旧配置`, `化凡成手札`, `闭关炼网关`, `出关即自动化`.
- `修真人设 + 互联网状态`: `本座闭关中`, `无情道破戒中`, `道心不稳`, `渡劫中`.
- `权限/产品梗 + 修真语境`: `已设权限`, `拒绝公测`, `限定皮肤`, `官方认证版`, `Pro Max`, `™`.
- `赛博/组织梗 + 个人编号`: `第77协议`, `Agent 77`, `77号机`, `老七办事处`.

Examples with acceptable tone:

- `飞书传令阵`: Feishu bot command entrypoint.
- `多端传令阵`: Feishu / WeChat / Telegram multi-channel command relay.
- `CLI剑匣`: collection of AI CLI tools.
- `渡劫排障录`: painful troubleshooting record.
- `掌天瓶记忆阁`: accumulating long-term notes or memories.
- `化凡手札`: converting technical complexity into readable notes.
- `天机阁小助手`: AI assistant for lookup, reasoning, analysis, and daily support.
- `77号技师`: cheeky bot/app name; best with a practical description.
- `第77协议`: secret-project style agent or protocol name.
- `老七办事处`: helpdesk / task handling / general assistant flavor.

Reject names that are funny but unclear. If a name needs explanation every time, choose a clearer one.

## Scene-Specific Guidance

For **Feishu / WeChat / Telegram bots**:

- Use a name that reads well in a chat list.
- Prefer roles: `小助手`, `传令使`, `接引使`, `办事处`, `天机阁`, `值夜使`.
- Pair with a short description that explains what it does.
- Example format:

```text
名称：天机阁小助手
描述：替你查资料、推演问题、整理杂务。
```

For **nicknames / aliases**:

- Prefer short status-like names: 4-8 Chinese characters is often best.
- Optional symbols are allowed, but do not rely on them for meaning.
- Keep stable aliases short, readable, and distinct from credentials.

For **apps / internal tools / agents**:

- Let the name be memorable and the description be practical.
- Good pairs:

```text
名称：77号技师
描述：专业处理疑难杂症，偶尔解决工作问题。
```

```text
名称：第77协议
描述：授权级智能代理，执行中。
```

For **credentials / web accounts**:

- Keep service and purpose explicit.
- Flavor is secondary; do not hide what the credential is for.
- Good pattern: `用途 + 服务 + 角色｜agent`.

For **account IDs / avatars / Bot icons / app icons**:

- Provide a complete prompt package, not just a name.
- Keep icon readability first: small size must still be recognizable.
- Prefer 1-2 strong visual symbols over crowded lore.
- Avoid relying on text inside the image; if using text, keep it to short marks like `77`, a seal, or a simple sigil.
- Use xianxia + modern tech mixing: 修士、器灵、令牌、玉简、飞剑、阵盘、符箓, plus AI eye, HUD, cyber glow, protocol badge, terminal/CLI motifs.
- Mention if the output should be `1:1`, `512x512`, `1024x1024`, transparent background, app-icon style, or avatar style.

## Modern Meme Mixing Decision

Modern internet memes should be included, but as seasoning:

- Use memes when they improve memorability or create a clean contrast with xianxia.
- Keep the operational role visible.
- Prefer evergreen memes and product-language jokes over short-lived platform slang.
- Avoid names that only work for a current trend and will look stale in a month.
- If choosing between pure xianxia and xianxia + meme, prefer the mixed version when the target is a public-facing bot, nickname, or app name.
- Prefer pure clarity when the target is a secret, credential, system config, or production infrastructure.

## Image Prompt Package

When the user asks for a visual, icon, avatar, app logo, account ID image, or image-generation prompt for a named object, output this structure:

```text
名称：
一句话定位：
图标/头像提示词：
负面提示词：
推荐规格：
```

### Prompt Requirements

The image prompt should include:

- **Subject**: person, artifact, bot avatar, seal, badge, sword, jade slip, array, bottle, pavilion, or protocol emblem.
- **Function cue**: show what the object does, such as command relay, troubleshooting, note capture, gateway routing, account identity, or AI assistant.
- **Xianxia cue**: cultivation robe, flying sword, talisman, jade slip, formation circle, spirit light, ancient seal, sect token, alchemy furnace, heavenly bottle.
- **Modern tech cue**: AI eye, cyber HUD, neon linework, terminal glyphs, protocol badge, mechanical components, app-icon polish.
- **Mood**: witty, clean, slightly cheeky, premium, not childish.
- **Legibility**: simple silhouette, strong contrast, recognizable at small sizes.

### Negative Prompt Defaults

Use or adapt:

```text
不要低俗元素，不要色情化，不要恐怖血腥，不要过多文字，不要复杂背景，不要廉价页游风，不要模糊，不要低清，不要杂乱构图，不要真实人物肖像侵权。
```

### Example Prompt Package

```text
名称：77号技师
一句话定位：专治疑难杂症的仙侠赛博 AI 助手。
图标/头像提示词：一个 1:1 应用图标，仙侠赛博混搭风。主体是一位白发修士技师，戴红色墨镜，手持发光玉简和机械工具，背后有淡金色阵法与蓝紫色赛博 HUD。画面中央隐约出现数字 77，像宗门工牌编号。整体气质专业、神秘、好玩，有“专治疑难杂症”的感觉。高辨识度，小尺寸仍清晰，干净背景，精致数字插画风。
负面提示词：不要低俗元素，不要色情化，不要恐怖血腥，不要复杂文字，不要复杂背景，不要廉价页游风，不要模糊，不要低清，不要杂乱构图，不要真实人物肖像侵权。
推荐规格：1:1，1024x1024；用于飞书/微信/Bot 头像时可裁成 512x512。
```

## Notion Naming Patterns

Use `NaN Xian·功能名` for Notion-facing surfaces.

Good patterns:

- `NaN Xian·万象炼智阁`: main AI learning and practice hub.
- `NaN Xian·万象阁传令使`: bot/connection that relays commands into the hub.
- `NaN Xian·镇魔排障录`: troubleshooting log.
- `NaN Xian·御器炼阵簿`: toolchain, IDE, CLI, gateway, and automation notes.
- `NaN Xian·问道修炼录`: learning journal or growth log.
- `NaN Xian·多端传令阵`: Feishu, WeChat, Telegram, email, or webhook entrypoints.

Avoid:

- Generic names like `Hermes Notes`, `AI Hub`, `Notion Bot`.
- Over-narrow names if the thing covers more than Hermes.
- Forcing global entities into `NaN Xian` when they are not Notion-local.
- Old Notion names that conflict with current canon: `听风楼·问道手札`, `听风楼·藏经阁巡山使`, `NaN Xian·藏经阁执事`.

## Rename Checklist

Before renaming:

1. Identify the object's real job: hub, bot, connection, credential, page, database, log, gateway, CLI, account, or workflow.
2. Decide whether it belongs to the global xianxia universe or a local namespace such as Notion's `NaN Xian`.
3. Pick 1-2 classic cultivation ingredients that match the function.
4. Add a modern tool/meme angle only if it improves memorability.
5. Choose a name that includes the role or metaphor clearly.
6. If the object needs an avatar/icon/account image, produce the Image Prompt Package.
7. Verify it does not conflict with current canon.
8. If credentials are involved, update only titles/notes/references; never expose secrets in chat or docs.
9. After changes, update local notes/indexes that mention the old name.

## Permission Boundary

For Notion + Hermes:

- `NaN Xian·万象阁传令使` should primarily access `NaN Xian·万象炼智阁` and its child pages/databases.
- Do not broaden access to unrelated Notion pages unless the user explicitly asks.
- Prefer one main hub over many scattered root pages.
